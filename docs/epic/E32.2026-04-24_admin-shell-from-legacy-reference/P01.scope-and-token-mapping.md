# P01: Scope and Token Mapping

## 목표
- 타 어드민 레이아웃을 참고해 Yamang으로 옮길 **블록 단위 범위**가 확정된다.
- 블록별로 Yamang **기존 컴포넌트 재사용** vs **신규 구현** vs **보류**가 구분된다.
- Admin 화면에서 관측되는 색·간격·타이포가 **`--ds-*` / `--ui-*` 매핑 초안**으로 정리되고, 토큰 갭(신규 토큰 필요 여부)이 식별된다.
- **antd 비도입·스펙 재작성** 원칙이 본 Phase와 Epic Readme 간에 모순 없이 기록된다.

## 구현 상세
- 참고한 타 어드민 레이아웃에서 `AdminLayout`, `Sidebar`, `Header`, 자주 쓰는 `templates`·페이지 패턴을 검토해 **이식 블록 목록**을 만든다.
- Yamang의 `src/app/components`, `src/domain/tokens`, 레이아웃 관례와 **대응 표**를 작성한다.
- 인라인 hex·고정 px는 나열하되, Yamang 정책상 **최종 구현은 토큰 우선**임을 표에 반영한다.
- Table·DatePicker·차트 등 **고복잡도** 항목은 P01에서 범위(자체 단순화 / 후속 Phase / 예외 검토)를 한 단락으로 박는다.
- 문서만 갱신하는 Phase이므로 **코드 변경은 필수 아님**. 다만 매핑 결과에 따라 Epic Readme `특이점`을 갱신한다.

### Yamang 대응 표 (재사용/신규/보류)
| 분류 | 항목 | 근거 |
| --- | --- | --- |
| 기존 재사용 | `Button`, `Input`, `Select`, `Badge`, `Avatar`, `Icon` | Yamang 기본 atoms가 존재하고 변형 속성으로 대응 가능 |
| 신규 구현 | `AdminShellLayout`, `AdminSidebarNav`, `AdminHeaderBar`, `AdminTableTemplate`, `AdminModalTemplate` | 현재 컴포넌트는 Lab/브랜딩 컨텍스트 중심이라 Admin 정보구조를 직접 담지 않음 |
| 보류(후속) | 가상 스크롤 그리드, 고급 DatePicker 팝오버, 차트 영역 | 고복잡도/의존성 이슈로 P01 범위 밖 |

| 영역 | 관측값(예시) | 토큰 후보 | 판정 |
| --- | --- | --- | --- |
| 콘텐츠 배경 | `#fff` | `--ds-color-bg-base` | 치환 가능 |
| 헤더 높이 | `64px` | `--nav-height` | 치환 가능 |

### 고복잡도 위젯 처리 방향 (결정)
- **Table:** P03/P04에서는 표준 템플릿(정렬/페이지네이션/필터 슬롯)만 우선 구현하고, 가상 스크롤/컬럼 고정 복합은 후속으로 분리한다.
- **DatePicker:** P03/P04에서는 `from`/`to` 입력 기반 단순화로 시작하고, 캘린더 팝오버 및 프리셋은 후속으로 분리한다.
- **Chart:** 본 에픽 본선 범위에서 제외하고 후속 에픽 후보로 관리한다. P04 검증 진입점에서는 KPI 카드/표로 대체한다.

### 작업 절차 (P01)
1. **블록 추출**: 타 어드민 레이아웃을 참고해 레이아웃/네비/헤더/표/필터/모달 관련 화면을 훑고, 중복 없이 블록 이름을 목록화한다.
2. **증거 기록**: 블록마다 "관측 위치(컴포넌트/페이지 식별명)"를 적고, 반복 사용 여부를 표시한다.
3. **Yamang 대응 매핑**: 각 블록을 `기존 재사용` / `신규 구현` / `보류`로 분류하고, 대응 후보(컴포넌트 또는 토큰 카테고리)를 적는다.
4. **토큰 치환 표 작성**: 색/간격/타이포 값을 `--ds-*`/`--ui-*` 후보에 연결하고, 매핑 불가 항목을 "신규 토큰 후보"로 분리한다.
5. **고복잡도 결정**: Table/DatePicker/차트는 자체 단순화/후속 분리/예외 검토 중 하나를 택해 근거와 함께 기록한다.
