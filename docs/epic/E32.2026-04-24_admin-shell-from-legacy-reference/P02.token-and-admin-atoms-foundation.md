# P02: Token and Admin Atoms Foundation

## 목표
- P01에서 식별한 Admin 셸 토큰 갭이 `--ds-*` 또는 Admin 별칭 토큰으로 확정된다.
- P03/P04 구현에 필요한 Admin 전용 atoms/parts(헤더 액션, 사이드 메뉴 아이템, 필터 바 베이스)의 최소 인터페이스가 정해진다.
- 기존 Yamang atoms(`Button`, `Input`, `Select` 등) 재사용 경계와 신규 구현 경계가 코드 스캐폴드 수준으로 분리된다.

## 구현 상세
- P01 `notes/token-mapping-log.md`의 신규 후보를 기준으로 토큰 후보를 확정하고, 네이밍 정책(`--ds-*` 우선, 필요 시 `--admin-*` 별칭)을 문서+코드에 반영한다.
- `src/app/components` 계층에서 재사용 가능한 Admin 파츠를 정의한다:
  - `AdminTopBarActions` (헤더 우측 사용자/상태 영역)
  - `AdminSidebarItem` (아이콘+라벨+활성 상태)
  - `AdminFilterBarBase` (검색/필터/리셋 액션 레이아웃)
- 인라인 값(색/간격/타이포) 금지 기준을 명시하고, P03/P04에서 허용되는 예외를 최소화한다.
- P02 완료 시점에 P03 생성 여부를 결정한다. 기준:
  - 신규 셸 레이아웃 블록 구현이 2개 이상이면 P03 독립 유지.
  - 아니면 P02에서 흡수 가능 여부를 체크리스트로 판단.

### 확정 토큰 목록 (P02)
`src/shared/styles/shell-variables.css`에 다음 Admin 별칭 토큰을 확정했다.

- 레이아웃/사이즈: `--admin-header-height`, `--admin-content-padding`, `--admin-sidebar-item-size`
- 사이드바 색/상태: `--admin-sidebar-bg`, `--admin-sidebar-text`, `--admin-sidebar-hover`, `--admin-sidebar-selected-bg`, `--admin-sidebar-selected-text`
- 상태 투명도: `--admin-nav-selected-opacity`, `--admin-nav-hover-opacity`

### Admin 파츠 최소 인터페이스 (P02)
| 컴포넌트 | 입력 props (핵심) | 상태 props (핵심) |
| --- | --- | --- |
| `AdminTopBarActions` | `userDisplayName`, `userEmail`, `roleLabel`, `environmentLabel`, `onLogout` | `isLoggingOut` |
| `AdminSidebarItem` | `label`, `icon`, `onClick` | `isActive`, `isCollapsed`, `disabled` |
| `AdminFilterBarBase` | `searchSlot`, `filterSlot`, `actionSlot`, `onRefresh`, `onReset` | `isExpandable`, `isExpanded` |

### 재사용 경계 vs 신규 구현 경계 (P02)
- **기존 재사용(확정):** `Avatar`, `Badge`, `Button`, `Input`, `Select`
- **신규 구현(확정):** `AdminTopBarActions`, `AdminSidebarItem`, `AdminFilterBarBase`
- **경계 원칙:** Admin 파츠는 레이아웃/상태 오케스트레이션만 담당하고, 입력/액션 원자 컴포넌트는 기존 atoms를 호출한다.

### P03/P04 공통 스타일 규칙 (P02 확정)
1. 색/간격/타이포를 JSX 인라인으로 직접 넣지 않는다.
2. 스타일은 CSS Module에서 `var(--ds-*)` 또는 `var(--admin-*)`로만 정의한다.
3. 임시 리터럴이 필요하면 토큰 정의 레이어(`variables.css`, `shell-variables.css`)에 먼저 등록 후 사용한다.

### P03 분리 유지 판단
- P01/P02 결과 기준으로 신규 셸 레이아웃 블록이 이미 `사이드바`, `헤더`, `메인 콘텐츠 캔버스` 3개 이상이다.
- 따라서 P03는 P02에 흡수하지 않고 독립 Phase로 유지한다.
