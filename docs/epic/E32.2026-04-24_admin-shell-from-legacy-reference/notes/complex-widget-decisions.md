# E32 P01 고복잡도 위젯 처리 결론

## 대상
- Table(대용량/가상 스크롤/복합 정렬)
- DatePicker(범위/타임존/커스텀 포맷)
- Chart(통계 대시보드 시각화)

## 결론
### 1) Table
- **P01 결정:** P03/P04에서 우선 "표준 테이블 템플릿"만 구현한다.
- 범위 포함: 서버/클라이언트 정렬, 페이지네이션, 검색/필터 슬롯, 행 클릭.
- 범위 제외(후속): 가상 스크롤, 컬럼 고정+리사이즈 복합, 트리 테이블.
- 근거: 현재 Yamang에 headless grid 기반이 없어 초기 Phase에 넣으면 일정 리스크가 큼.

### 2) DatePicker
- **P01 결정:** P03/P04에서는 기본 입력 2개(`from`/`to`) 기반으로 단순화한다.
- 범위 포함: 날짜 문자열 입력 + 검증 + UTC/KST 변환 유틸 연동.
- 범위 제외(후속): 팝오버 캘린더 UI, 복합 프리셋(이번주/지난달), 시간 선택.
- 근거: 접근성·키보드 상호작용까지 포함된 완성도 확보에 별도 설계가 필요.

### 3) Chart
- **P01 결정:** 본 에픽 본선 구현 범위에서 제외하고 후속 에픽 후보로 분리한다.
- 대체안: P04 검증 진입점에서 카드/표 기반 KPI 요약으로 대체.
- 근거: 차트 라이브러리 의존성 추가 시 "Ant-free 최소 의존" 원칙과 설계 판단이 필요.

## Phase 반영 메모
- P02 생성 시 토큰 후보 확정과 함께 `Table/DatePicker` 단순화 스펙을 인터페이스 문서로 격리한다.
- P03/P04 목표/체크리스트에는 "후속 제외 범위"를 명시해 scope creep를 방지한다.
